# Scientific and application test strategy

The original 16 core tests remain unchanged. The expanded Python suite exercises analytical network solutions, conservation and bound properties over seeded graphs, paired sensitivity, counterfactual failure classification, analytical Darcy–Weisbach chains and parallel pipes, minimum-cut witnesses, adversarial search, candidate ancestry, independent primal audits, evidence tampering, sealed scenario splits, deterministic replay, infeasible synthesis, durable jobs, cancellation, API contracts and interactive evidence downloads.

Run `.venv/bin/python -m unittest discover -s tests -v`. Tests require the `test` and `api` extras. Multiprocessing and local API tests need a normal process/network environment; restricted execution environments can prevent process startup.

The command application uses Vitest and Testing Library against projections generated by Python, rather than hand-invented scientific fixtures. Playwright runs against the actual local Python API and browser: scientific canvas, comparison, failure intervention, rejected ancestry, provenance, historical baseline, mobile inspection, and asynchronous experiment completion. Run `npm --prefix apps/command test`, then start the two local servers described in README and run `npm --prefix apps/command run test:e2e`. Background-job tests use a fresh recorded seed to avoid receiving a cached completed job. This does not change scientific assertions.

Numerical claims require analytical checks where available and independent recomputation of feasibility. Monte Carlo confidence is never tested as formal verification. Reproducibility compares canonical scientific payloads, excluding timestamps and timing metadata. The preserved historical artifact is also checked byte-for-byte. Performance measurements are descriptive benchmarks, not portable timing assertions; software GPU results and failed intermediate measurements remain evidence.

Phase 3 adds dimension algebra/conversion tests, independent closed-form PDD/full-demand/parallel/reverse-flow cases, dry-equilibrium and tamper regressions, tank balance/exhaustion/step-refinement checks, operational cascade tests, SMT-LIB replay/exhaustive graph checks, sealed hydraulic split/ancestry/replay tests, no-budget negative evidence, hydraulic API/job/download contracts, and real projection/pressure/timeline/fallback frontend tests. Live-browser hydraulic coverage requires the actual inspector disclosure and catches DOM lifecycle errors on WebGL/SVG switching. The original 43 Python, five frontend and three browser tests remain unchanged in their assertions.

## Phase-4 expansion

Preserve the original 67 tests and all original browser/frontend assertions. New scientific tests use controlled Gaussian/noiseless truth recovery, dimension failures, local rank deficiency, validation poisoning without training change, information weighting, conditional sensor gains, explicit knowledge categories, exact hazard probabilities, seeded cascade/ensemble equality, independent hydraulic audits, scheduled recovery, bounded tool stopping, held-out confidence requirements, counterexample simulation and process-worker contract/replay.

New frontend tests consume real Python projections and reject incompatible observation units, unsupported calibrated/proof badges and changed GPU velocity. Browser checks cover actual observation/residual comparison, stored stochastic events, uncertainty inspection, guided presentation, mobile width, GLSL rendering, worker responsiveness and no browser page errors. Scientific replay compares hashed payloads; report generation validates the package before projecting prose.

Resumed diagnostic tests require exact stored failed-state replay, negative design retention, fixed conditional mechanisms and hash tamper rejection. Local covariance tests check exact seed replay, zero-covariance recovery of independent stored point predictions and rejection of invalid covariance/budgets. Failed-case projection preserves unknown solver states separately; frontend checks reject mismatched GPU data and disable temporal playback for independent scenario cases. Build/type checking remains separate from runtime interaction tests.
